# 设计与哲学

这个项目把群聊当成 Pi 的另一种工作入口：确定性代码处理 Telegram 的收发和路由，Pi 处理会话、模型和工具。目标是长期维护一层薄封装。

## 1. 什么时候说话由代码决定

@、回复、叫名字会明确触发 bot；普通消息按概率最多交给一个 bot，忙碌或冷却中就跳过，不改投。bot 之间默认不互相触发，管理员可以开启 `/fire`。

直接点名的待答内容保存在 Pi 文档里，跨重启和压缩保留。模型健康结束却没有公开回应时，最多补问一次；仍然沉默则等下一次输入。Telegram 发送结果未知时不重发，并结清本轮已见的待答内容，以避免重复消息。

## 2. Telegram、消息归档和 Pi 会话各有职责

1. Telegram 负责传输，不用于恢复历史。
2. `data/agent.db` 保存群消息、编辑、引用和媒体描述的不可变事件，供路由和 `tg_messages` 检索。
3. `data/pi/<bot>.sqlite` 由 Pi Durable 保存会话、队列、后台任务和累计用量。

每批消息只交给 Pi 一次；历史归档和模型当前上下文不必一样大。重启恢复依赖本地持久化状态，备份时应保存整个 `data/`。

## 3. Pi 原生优先

Pi 1.5.0 提供会话持久化、steering、重试、压缩、child conversation、后台工具任务、用量账本、coding tools、图片处理和 codemode。研究任务读取工作流的 `AGENTS.md`，与主 bot 共用隔离工作区；不再启动另一份 Pi CLI 或维护任务 RPC。

本仓库保留与 Telegram 直接相关的东西：群内路由、发送是否能重试的判断、管理员命令、hybrid 描述缓存、搜索服务和 rootless Docker 部署。provider 的整流截止与代理 HTTP 413 归一化仍需薄适配，因为 Pi 1.5.0 还没有覆盖这些实际失败边界。

Pi Durable 的接口仍属实验性，因此各包精确锁定 1.5.0；升级时一起更新并检查恢复和发送边界。

## 4. 不花冤枉钱

- 路由、状态查看和管理命令由代码处理，只有 `/compact` 会调用模型。
- 同一个上下文片段内，固定 system、人设、工具和已有输入，只追加新消息。压缩、换模型和 `/new` 会建立新前缀。
- 群消息批次与待答原文共享有限字符预算；搜索返回短结果，网页分页，脚本过滤后再给模型。
- hybrid 把每份媒体描述一次并跨 bot 复用；要核对细节时才看原图。Pi 保存原生图片字节，不需要一套外部图片引用协议。
- 摘要采用当前聊天模型和 reasoning effort，固定预留 16,384 token，关闭提前后台压缩。原生摘要排除图片与 thinking；加密签名成本和超大摘要仍有局限，不能承诺任意输入都能压缩成功。
- 最终单独调用 `send` 可结束本轮；codemode 内的进度发送可继续执行。只有 send 会公开到群。

`/status` 的累计用量来自 Pi，包含 child 与历史，`/new` 不清零。provider 目录的零单价不代表免费，账单以服务商为准。

## 5. 提示词只补群聊语义

人设描述人格与回应风格，工具参数由 Pi 的原生 schema 解释。提示词保留群消息格式、公开发送规则和源码地址，不重复装入完整工具教程。bot 可以阅读自己的代码来解释实现。

每批 sticker 候选作为独立系统附注固定在该批后面，仅用于模型请求；它们不进入持久化 user 正文，因此原生摘要不会把候选当成群友说过的话。

## 6. 安全靠机制

- codemode 在 Pi QuickJS worker 内执行，没有宿主 API、直接网络或文件系统，只能调用允许的工具。
- 原生 read/write/edit/bash 经 pi-env 进入 rootless Docker：无宿主目录或凭据，只读根目录、资源上限和独立 `/work` 卷；文件发送另做路径和大小检查。
- 搜索拒绝内网、回环和云元数据地址。
- 状态修改命令检查管理员数字 ID，控制消息永不进入模型上下文。
- 重启按 Pi 的工具 replay 规则恢复；已经开始但结果未知的危险操作不盲目重做。`/new` 等待旧工作停止后再重置。

## 7. 先想清楚再写

先查 Pi 能否承担职责，再决定保留什么。删除重复机制优先于增加抽象；不保留旧字段和兼容执行链。配置只有 `telegram.config.ts`、Pi 设置和 `.env`，`/set`、`/model` 验证后原子写回同一配置。

不搞 TDD，也不堆锁定实现细节的单测。保留 cache、零外网和关键安全守卫，通过类型检查、离线原生执行以及明确授权的真实服务验证来检查行为。

## 刻意不做的事

- 不用 Telegram Rich Message 发言，保持旧客户端可读。
- 不自动打开群里的链接。
- 一份部署只对应一个群；第二个群使用独立目录和 token。
- 不在 Telegram 发送结果未知时重发。
