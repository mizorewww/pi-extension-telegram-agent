# 为什么它省钱

本项目不承诺固定的节省比例：价格、群活跃度、persona 长度和 provider 的 cache 行为都会变。实际效果以 `/tg status` 和群里 `/status` 为准。下面是它避免浪费的方式。

1. **不该调用模型时就不调用。** 是否回应由本地代码决定：@、回复、点名必定回应；普通消息按概率最多交给一个 bot，忙碌或冷却中就跳过。打开 Pi、翻历史、看用量、群内管理命令都不调用模型。

2. **最大化 prompt cache 复用。** 每个 bot 的 system prompt、persona、sticker 目录和工具说明保持逐字节不变，新消息只追加在后面，不改写前面发过的内容。provider 支持 prompt cache 时，重复部分按更低的价格计费。

3. **每轮只发送需要的内容。** 完整历史留在本地数据库，每轮只发送有上限的新消息（默认 12,000 token），被直接点名的消息优先。上下文到阈值时用便宜的摘要模型压缩，而不是无限变长。

4. **媒体按身份只处理一次。** 同一张图片或视频，无论多少个 bot 看到，只描述（vision 模式）或准备（context 模式）一次，结果复用。视频只抽 1–3 帧。

5. **工具结果有上限。** 搜索最多 5 条短结果，网页正文最多约 2,000 token；群里的链接不会被自动打开。

6. **一次发言就结束本轮。** bot 发言成功后本轮立即结束，不会多花一次请求“确认”；被点名却没回应时最多补答一次。

评估自己的部署时，比较同一 provider、同一 persona、相近活跃度的时间段。部分 provider 的模型目录单价为 0（例如订阅制），这时显示的费用不代表实际账单，以 provider 账户为准。
